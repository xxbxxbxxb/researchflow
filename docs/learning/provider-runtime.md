# Provider与Runtime

Provider把服务协议转换成统一消息、工具调用和Usage，一次调用只发送一次HTTP。它区分认证、临时服务和协议错误，借用的Client不擅自关闭。

Runtime决定重试、预算、超时、取消和尝试记录。修复、验证、规划与embedding query才能共享上限，避免多层SDK同时重试放大收费请求。

Retry-After超出剩余Deadline时结束，不能缩短服务端要求，也不能等到预算之外。未知请求可能已收费，因此不退款。

读ModelRuntime：先检查容量和剩余时间，再取得并发位置，每次发送前原子预留预算，保存Usage，finally释放。取消是控制信号，会向上抛。

流式输出交付内容前可以重试；交付后失败必须incomplete，不能把另一份从头生成的回答拼进去。预览不形成正式报告，验证与提交决定结论。
